# ユースケース

各ガイドは、アプリケーションがすでに持っているデータから始まり、その結果をどう使うかを示します。各領域のページと生成された API リファレンスを補うものです。

各ガイドは、素材がノートイベントかコード記号としてすでにメモリ上にあり、調と拍子は分かっているか検出に任せる、という状態を前提とします。それより手前の段階はここでは扱いません。度数・終止形・ボイシング・軸和音（ピボットコード）といったガイドが使う音楽用語については、[入門](../primer/index.md)を参照してください。

いずれもクラス API で書かれています。最初から最後まで通す流れこそクラスの用途だからです。`Score` は音符を拍子・テンポ・調とともに保持し、`Composer` は1曲を書くための調・テンポ・シードを保持するので、問いを重ねても同じ事実を言い直さずに済みます。クラスが受け持たない手順では関数を呼び、その理由を本文で述べます。

解析と検査:

- [DAW ワークフロー](daw-workflow.md): `Score` でトラックから和声を推定し、`Composer` でそれに対するベースラインを書きます。
- [楽曲の解析](piece-analysis.md): 1つのスコアから調区間、終止、縮約、フレーズ、セクション、モチーフを求めます。
- [転調レポート](modulation-report.md): 調の変化を、ピボット・信頼度・隣り合う調どうしの関係とともに提示します。
- [和声課題チェッカー](harmony-exercise-checker.md): `Voicing` に対して和声課題と種目対位法の違反を報告します。

素材の生成:

- [生成アレンジ](generative-arrangement.md): シードを固定した1つの `Composer` で進行、パート、ドラムを書き、演奏可能性を検査します。
- [コード譜の取り込み](chord-chart-import.md): 入力されたコード記号を `Timeline`、ボイシング、ベースラインにします。
- [パートの準備](part-preparation.md): パートを `Instrument` に合わせ、奏者が読む音高で書き出します。

すべての例は MIDI ピッチ番号と4分音符を単位とする拍を使います。ファイル入出力、MIDI の解析、記譜、音声解析、再生はホストアプリケーションの担当です。その境界での変換は[相互運用](../interoperability.md)を参照してください。
